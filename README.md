# تطبيق منصة الحلم — Flutter MVP

تطبيق مستقل لـAndroid وiOS مرتبط بنفس Backend وقاعدة بيانات منصة الحلم.

## ما تم تنفيذه

- خمس شاشات تعريفية قبل التسجيل.
- اختيار نوع الحساب: لاعب، نادٍ، أكاديمية، وكيل، مدرب، مسوّق.
- دخول وإنشاء حساب برقم الهاتف وOTP عبر مسارات المنصة الحالية.
- واجهة لاعب تحتوي على:
  - الرئيسية.
  - البحث عن لاعبين وعرض كروتهم.
  - سينما لاعبين عمودية بأسلوب الفيديو القصير.
  - الفرص والتقديم عليها.
  - الملف الرياضي والسيرة الذاتية.
- واجهة الحسابات الأخرى تحتوي على إدارة اللاعبين وإنشاء كود دعوة.
- قائمة للأقسام غير المنقولة بعد تفتح صفحة الويب المناسبة مؤقتًا.
- جميع أنواع الحسابات معروضة كمجانية.

## مبدأ عدم فقد الحقول

`UserProfile.values` يحتفظ بكامل صف اللاعب القادم من قاعدة البيانات، بما في ذلك
الحقول التي لا تعرضها نسخة التطبيق الحالية. عند الحفظ تُدمج التعديلات مع الحمولة
الأصلية بدل إنشاء كائن ناقص. الحقول الأساسية في جدول `users` تُحدّث منفصلة.

يجب إبقاء هذا السلوك واختبار `test/profile_merge_test.dart` عند إضافة أو تعديل
حقول جديدة في الويب.

## التشغيل

```bash
flutter pub get
flutter run \
  --dart-define=API_BASE_URL=https://el7lm.com \
  --dart-define=WEB_BASE_URL=https://el7lm.com \
  --dart-define=SUPABASE_URL=https://PROJECT.supabase.co \
  --dart-define=SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx
```

لا تضع `service_role` أو أي مفتاح سري في تطبيق الموبايل. المفتاح المسموح هو
المفتاح العام `publishable` فقط.

## المصادقة

التطبيق يطابق تدفق الويب الحالي:

1. `POST /api/otp/send`
2. التسجيل: `POST /api/auth/verify-otp-and-check`
3. إنشاء المستخدم الجديد: `POST /api/auth/create-user-with-phone`
4. الدخول: `POST /api/auth/otp-login`
5. إنشاء جلسة Supabase باستخدام بيانات التبادل المؤقتة التي يرجعها Backend.

قبل الإطلاق العام يُنصح باستبدال إرجاع كلمة المرور المؤقتة من Backend برمز
تبادل أحادي الاستخدام أو جلسة/رابط OTP أصلي من Supabase.
