## 1. بنية وتدفق الإشعارات الحالي (Architecture Review)

### قنوات الإشعارات المفحوصة:
1. **السحب الدوري (Polling):**
   - **[مؤكد بالكود]** يعتمد تطبيق الهاتف حصرياً على مؤقت دوري في `app_shell.dart:64-67` يقوم باستدعاء دالة `_fetchUnreadCounts()` كل 60 ثانية بشكل مستمر طالما الشاشة الرئيسية نشطة.
2. **الاستماع اللحظي (Supabase Realtime):**
   - **[مؤكد بالكود بالغياب]** لا توجد أي قنوات اشتراك لحظية (`Supabase Realtime Channels`) مفعلة للإشعارات أو الرسائل داخل تطبيق الهاتف.
3. **الإشعارات السحابية الفورية (Push Notifications - FCM):**
   - التطبيق يفتقر إلى استقبال إشعارات الدفع (FCM Push) عند إغلاق التطبيق.
4. **تحديث الخلفية (Background Refresh):**
   - لا توجد مهام استطلاع في الخلفية (Background Tasks)، والإشعارات تتوقف كلياً عن التحديث فور خروج المستخدم من واجهة التطبيق.

## 2. تفصيل استعلامات الاستطلاع الدوري (Per-User Query Profile)

في كل دورة استطلاع (كل دقيقة)، تنفذ دالة `_fetchUnreadCounts()` (`app_shell.dart:173-196`) ما يلي:
1. استدعاء `fetchConversations()`: استعلام جدول `conversations` (استعلام 1).
2. استدعاء `fetchNotifications()` (`data_service.dart:58-63`):
   - استعلام جدول `notifications` بحد 100 سجل (استعلام 2).
   - استعلام جدول `interaction_notifications` بحد 100 سجل (استعلام 3).

**المعدل الثابت:** **3 استعلامات قاعدة بيانات كاملة لكل مستخدم نشط في كل دقيقة** (أي 180 استعلاماً / ساعة / مستخدم).

## 3. دراسة سيناريوهات النمو والضغط التشغيلي (Load Scenarios)

### الافتراضات الهندسية للحسابات:
- **المستخدم النشط (Concurrent Active User):** مستخدم يفتح التطبيق في الواجهة الأمامية (Foreground).
- فترة بقاء المستخدم في الجلسة: ساعة واحدة في المتوسط خلال أوقات الذروة.
- يتم تطبيق الحساب على طلبات فحص الإشعارات فقط (دون احتساب تصفح المقاطع أو تحديث الملف الشخصي).

## 4. مشكلة الـ N+1 في تمييز الإشعارات كمقروءة

**المصدر:** `mobile/lib/services/data_service.dart:103-108`

```dart
Future<void> markAllNotificationsRead() async {
  final notifications = await fetchNotifications();
  for (final notification in notifications.where((item) => !item.isRead)) {
    await markNotificationRead(notification); // استعلام منفصل لكل إشعار!
  }
}
```

- إذا كان لدى المستخدم 30 إشعاراً جديداً وضغط على زر "قراءة الكل"، يقوم التطبيق بإطلاق **30 طلب UPDATE متتالي** للشبكة.
- هذا يزيد من زمن إتمام العملية وقد يؤدي لانقطاع التحديث في حال ضعف اتصال المستخدم بعد أول بضعة إشعارات.
